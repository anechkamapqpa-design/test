# Мини-CRM для заявок агентства

Лиды сами приходят из Telegram-бота, их можно завести руками, разметить тегами и найти по тегу, статусу или тексту.

- **Живая ссылка:** https://test-sepia-delta-94.vercel.app
- **Бот:** https://t.me/nfjhwufgoqhwiodawhfrhi_bot
- **Код доступа:** передаётся вместе со ссылкой в сообщении со сдачей. В репозиторий не кладём: он публичный, а код открывает базу лидов.

Набросок продукта: [PRODUCT.md](PRODUCT.md). Короткий разбор, как делали: [REVIEW.md](REVIEW.md). Журнал решений: [DECISIONS.md](DECISIONS.md). Промпты: [prompts/](prompts/).

## Стек

- Фронтенд: Vite + React 18 + TypeScript + Tailwind CSS, одна страница, без UI-библиотек и state-менеджеров.
- Бэкенд: serverless-функции Vercel в `/api` (TypeScript, Node).
- База: Supabase Postgres, доступ только из `/api` через service role.
- Telegram: Bot API через вебхук, обычный `fetch`, без библиотек.

```
Telegram ──вебхук──▶ /api/telegram ──▶ Supabase ◀── /api/leads, /api/tags ◀── SPA (x-app-key)
                     (диалог в bot_sessions)
```

## Схема данных

Миграция: [supabase/migrations/001_init.sql](supabase/migrations/001_init.sql).

| Таблица | Что хранит |
|---|---|
| `leads` | имя, контакт, запрос, `source` (`bot` / `manual` / `telegram_personal`), `status` (`new` / `in_progress` / `done` / `rejected`), `tg_chat_id`, `tg_username` |
| `tags` | название (уникальное), цвет |
| `lead_tags` | связь лид ↔ тег |
| `bot_sessions` | шаг диалога и черновик заявки по `chat_id` |
| `events` | история лида: `lead_created`, `status_changed`, `lead_edited`, `tag_added`, `tag_removed` |

**RLS включена на всех таблицах, политик нет сознательно:** с анонимным ключом база закрыта полностью, весь доступ идёт через service role из `/api`.

## API

Все ответы в JSON, ошибки в виде `{ "error": "текст" }`. Везде, кроме `/api/health` и вебхука, нужен заголовок `x-app-key`, без него ответ `401`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | `{ok:true, db:true}`, реальный запрос к базе |
| POST | `/api/telegram` | вебхук бота, проверяет `X-Telegram-Bot-Api-Secret-Token` |
| GET | `/api/leads?tag=&status=&q=` | лиды с тегами, новые сверху |
| POST | `/api/leads` | ручной лид `{name, contact, request}` |
| PATCH | `/api/leads/[id]` | `status`, `name`, `contact`, `request` |
| DELETE | `/api/leads/[id]` | удалить лида |
| GET | `/api/tags` | теги с количеством лидов |
| POST | `/api/tags` | новый тег `{name, color}` |
| POST / DELETE | `/api/leads/[id]/tags` | навесить или снять тег `{tagId}` |

## Переменные окружения

Шаблон: [.env.example](.env.example). Задаются в Vercel → Settings → Environment Variables. После изменения нужен новый деплой.

| Переменная | Откуда взять |
|---|---|
| `SUPABASE_URL` | Supabase → Project Settings → API → Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | там же, ключ `service_role` (или новый `secret`). Только на сервере, никогда не с префиксом `VITE_` |
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` |
| `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка, её же передаём в `setWebhook` |
| `APP_ACCESS_KEY` | код входа в интерфейс, придумываете сами |

## Установка вебхука

```bash
curl -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  -d "url=https://test-sepia-delta-94.vercel.app/api/telegram" \
  -d "secret_token=$TELEGRAM_WEBHOOK_SECRET"
```

Проверка:

```bash
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getWebhookInfo"
```

Если бот молчит, первым делом смотрите в ответе поле `last_error_message`.

Можно и без ручного копирования токена: положить переменные в `.env.local` и запустить `node scripts/set-webhook.mjs https://test-sepia-delta-94.vercel.app`. Скрипт поставит вебхук и покажет `getWebhookInfo`, токен в консоль не печатает.

## Локальный запуск


Функции `/api` локально проще всего гонять через `npx vercel dev` с теми же переменными.

## Чего сознательно не делаем

- Пункт 2 задания, подключение личного телеграма как источника лидов, **не реализуем кодом**. Задание это разрешает. В схеме данных место под него уже есть: `source='telegram_personal'`. В наброске продукта описано, как это делается через MTProto ([PRODUCT.md](PRODUCT.md)).
- Роли и права, несколько пользователей, аудит доступа.
- Уведомления, воронка, аналитика, экспорт.
- Дедупликация лидов: один человек, написавший дважды, создаёт двух лидов. Решение осознанное, в продукте это закрывается склейкой по контакту.
- Тесты. На трёхдневном сроке вместо тестов делаем ручной чек-лист ниже.

## Как проверить

1. Открыть живую ссылку, ввести код доступа.
2. Написать боту `/start` и ответить на три вопроса, не закрывая страницу CRM.
3. Через 15 секунд лид появится сам, с бейджем «бот» и телеграм-ником.
4. Навесить тег, создать новый тег, снять тег, отфильтровать по тегу, найти лида поиском, сменить статус и обновить страницу.

## Если что-то не работает

1. Бот молчит: `getWebhookInfo`, поле `last_error_message`.
2. Ошибка 500 в функции: Vercel → Logs.
3. База не отвечает: переменные заданы в Vercel, а не только в `.env.local`, и после них был новый деплой.
4. Данные не отдаются: RLS включена, значит запрос идёт не с service role ключом.
5. Фронтенд получает 401: не доехал заголовок `x-app-key`.
