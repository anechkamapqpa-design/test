## Что было интересно

- **Секреты.** ИИ отказался вписывать ключи в Vercel и запускать скрипт с токеном. Вместо этого он сделал `.env.local` (в `.gitignore`) со всем, кроме двух секретов, и скрипт `scripts/set-webhook.mjs`: тот ставит вебхук и не печатает токен. Получилось удобнее, чем копировать токен в curl.
- **Проверка без кода доступа.** ИИ проверял то, что можно проверить без пароля: 401 на всех 8 эндпоинтах, отсутствие секретов в бандле на деплое, вёрстку на 375px. Сценарии под кодом проходила я. В README в чек-листе отмечено, кто что проверял.
- **Не по шаблону.** Для пункта 2 нашёлся путь проще MTProto: Telegram Business позволяет подключить того же бота к личному аккаунту. Описан в [PRODUCT.md](PRODUCT.md) как первый вариант.

## Что бы сделала за ещё одну неделю

1. **Личный Telegram через Telegram Business** (`business_message` в том же вебхуке), затем MTProto-воркер для аккаунтов без Premium.
2. **Склейка дублей** по контакту и `tg_chat_id`: повторное обращение становится событием у существующего лида, а не новым лидом.
3. **Уведомление менеджеру** в Telegram о новом лиде с кнопками «в работу» и «спам».
4. **Карточка лида с историей** из `events` и заметками, ответ клиенту прямо из CRM через бота.
5. **Пользователи** через Supabase Auth вместо общего кода, RLS-политики и автор каждого изменения в `events`.
6. **Автотесты** на диалог бота (это чистая функция «шаг + сообщение → шаг + ответ») и смоук-тест API в CI.
