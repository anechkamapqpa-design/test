# DECISIONS

Журнал развилок. Каждая запись: что решала, какие были варианты, почему этот.

## 1. Tailwind: v4 через плагин Vite
- **Что:** как подключить Tailwind к Vite.
- **Варианты:** v3 с `tailwind.config.js` + PostCSS; v4 с `@tailwindcss/vite`.
- **Почему v4:** одна строка `@import "tailwindcss"` и плагин, без двух конфигов. Меньше мест, где можно ошибиться на сжатом сроке.

## 2. Один деплой на Vercel, SPA-rewrite кроме /api
- **Что:** как отдавать фронт и API с одного домена.
- **Варианты:** отдельный бэкенд (Render/Railway) + статика; всё на Vercel.
- **Почему Vercel:** один репозиторий, одна ссылка, нет CORS. `vercel.json` переписывает всё, кроме `/api/`, на `index.html`.

## 3. Service role ключ только на сервере
- **Что:** как фронт получает данные из Supabase.
- **Варианты:** supabase-js в браузере с anon-ключом и RLS-политиками; все запросы через `/api` с service role.
- **Почему `/api`:** service role обходит RLS, в бандле он равен открытой базе. Держим его в `api/_lib/db.ts`, без префикса `VITE_`, фронт ходит только в `/api`.

## 4. RLS включена, политик нет
- **Что:** как закрыть таблицы от прямого доступа.
- **Варианты:** выключить RLS; написать политики под anon/authenticated; включить RLS без политик.
- **Почему без политик:** с anon-ключом база закрыта полностью, и это то, что нужно. Единственный путь к данным идёт через service role в `/api`. Политики понадобятся, когда появятся пользователи и роли, сейчас их нет.

## 5. /api/health проверяет базу реальным запросом
- **Что:** чем доказывать `db:true`.
- **Варианты:** просто проверить, что заданы переменные; сделать запрос.
- **Почему запрос:** `count` по `tags` с `head:true` ловит и неверный ключ, и непримененную миграцию. Переменные могут быть заданы, а база при этом недоступна.

## 6. Вебхук, а не polling
- **Что:** как получать сообщения боту.
- **Варианты:** long polling `getUpdates`; вебхук `setWebhook`.
- **Почему вебхук:** на Vercel нет постоянно живого процесса, функция живёт секунды и только пока есть запрос. Polling там некому крутить. Вебхук сам будит функцию на каждое сообщение.

## 7. Вебхук всегда отвечает 200 (кроме чужого секрета)
- **Что:** что возвращать телеграму, если внутри упало.
- **Варианты:** честный 500; всегда 200 и лог.
- **Почему 200:** на не-2xx телеграм повторяет то же обновление, и диалог залипает на одной ошибке. Ошибку пишем в лог Vercel, пользователю отвечаем понятным текстом. 401 только на неверный `X-Telegram-Bot-Api-Secret-Token`: это не телеграм, повторять нечего.
